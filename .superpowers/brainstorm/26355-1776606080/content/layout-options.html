Bit Analyzer: Layout Direction

How should the bit analysis tools be organized within the existing app?

A

New /bits Route (Full Page)

Dedicated page with its own route. Layout: frame selector + playback controls on left, analysis panels stacked vertically on right. Fits all 7 views but requires scrolling.

Preview: Full Page Layout
Frame ID Selector
Playback Slider + Play/Pause
Frame List (filterable)
Bit Flip Diff (consecutive frames)
Flip Heatmap
Stability / Entropy Bars
Correlation Matrix
Value Clustering
Mux Toggle

Pros

  • Plenty of space for all views
  • Clean URL for sharing
  • Simplifies existing pages

Cons

  • Navigation away from editor
  • Requires scrolling on smaller screens
B

Tabbed Panel on Existing /frames Page

Add a tabbed analysis panel below the frame viewer. Each tab shows one analysis method. Less scrolling, but hidden views require tab switching.

Preview: Tabbed Panel
Frame ID Selector + Playback
Frame List
Diff Heatmap Stability Entropy Correlation Clustering
Active Tab Content
Mux Toggle

Pros

  • Context preserved (see frames while analyzing)
  • No page navigation
  • Tab switching is fast

Cons

  • Can't see all views simultaneously
  • Crowds existing frame viewer
  • Tab proliferation (6 tabs)
C

Hybrid: New Route + Shared Context

Dedicated /bits route with a compact summary strip (diff + heatmap side-by-side), then expandable sections for deeper analysis. Mux toggle as a top-level control.

Preview: Hybrid Layout
Mux Toggle (top control)
Frame ID Selector
Playback Slider + Play/Pause
Frame List
Bit Flip Diff
Flip Heatmap
Stability & Entropy Analysis
Stability bars + Entropy bars
Change Correlation
Correlation matrix
Value Clustering
Clustered value display

Pros

  • Most-used views always visible (diff + heatmap)
  • Deeper views expandable on demand
  • No tab switching for primary workflow
  • Dedicated route for focus

Cons

  • Expandable sections are less discoverable
  • Still requires scrolling on small screens
